# IT-test

## 定位

`it-test` 只消费已确认任务意图、整合后的任务信息集合和选定流程中的接口契约、验收规格与执行边界；不重新定义预期，也不选择后续流程节点。

它以真实 HTTP/API 入口验证参数绑定、鉴权、序列化、服务编排、数据读写和必要副作用。测试保持黑盒：代码只用于识别风险场景，不能代替可观察结果。语言、框架、测试组织、fixture、模板和环境细节服从业务项目规则、Profile 与本 Skill 资产。

输入缺失、事实冲突或流程不适用时，返回缺口、仍有效事实和恢复条件。

## 执行

1. 读取已有 IT、接口契约、验收规格、项目规则和必要现状，确定待验证 API、回归范围、数据条件与允许副作用。
2. 选择时机：测试先行有价值时，先通过真实 HTTP 建立目标 Red；仅需最终验收时，复用或补充已有断言后运行目标 API 与相关回归。接口尚不存在时只写可编译骨架，不为制造 Red 破坏编译或伪造环境。
3. 复用项目已有 HTTP 客户端、启动方式和测试结构；没有更权威结构时，按实际 JUnit 版本参考 `assets/ControllerIT.junit4.java.template` 或 `assets/ControllerIT.junit5.java.template`。
4. 只覆盖会产生不同可观察结果的正常、参数、权限、状态、规则、异常、事务和副作用场景，不按内部代码分支凑用例。每个 API 保留独立可识别的真实请求和断言。
5. 断言响应结构、业务状态、关键字段以及必要的数据和副作用。正向命中数据可用时，验证足以证明字段映射、关系或统计含义的业务结果，不能只断言 HTTP 或业务成功码。
6. 运行目标集测和相关回归；完成说明只使用本轮结果，区分已通过场景、未覆盖场景和阻塞项。

## 服务与数据

1. 先从项目规则、README、脚本、运行配置和当前进程确认实际启动方式；服务未就绪时，默认在确认不会造成未授权外部写入或不可逆副作用后自行启动。
2. 使用项目健康检查、目标 API 探测或日志确认就绪。连接拒绝只表示服务尚未就绪，先完成启动和诊断，不能作为业务 Red 或切换测试类型的依据。
3. 缺少凭据、配置、不可访问依赖、未授权外部状态变更或启动仍失败时，报告失败证据、当前阶段、所需条件和恢复动作；不擅自停止或重启用户已运行的服务。
4. 真实 API 必须经过项目实际的鉴权、过滤器、拦截器和网关上下文；不得以 Mock 鉴权或临时绕过替代它。凭据和配置的存放方式服从项目规则。
5. 优先复用已验证且适用的真实数据；可隔离、允许且可清理时，可通过真实 API 或数据库建立前置数据。数据来源本身不能证明通过，必须断言本轮响应、状态或副作用。
6. 缺少非空命中数据但空结果符合契约时，该空结果可证明链路和空结果行为，不得升级为非空字段、关系或统计已验证；它不阻塞无关场景，但必须作为未覆盖项报告。
7. 写接口先确认允许的状态变化与数据、缓存、消息、审计或外部同步副作用；创建的数据应可识别、隔离并按项目规则处理。

## 失败取证与回交

测试失败时，结合真实请求、响应、服务日志、调用链、数据源和接口契约定位责任层；不能为获得 Green 改写预期、删除断言、放宽断言或跳过场景。

- 测试代码或预期错误：依据已确认契约和真实序列化行为修正数据准备、请求或断言，重跑原场景。
- 生产代码错误：返回根因证据、可执行修复建议、受影响范围和恢复条件；本节点不修改生产代码。
- 测试数据不足：说明每个受影响 API 的请求、缺少的业务属性或关系、已尝试来源及恢复位置；继续执行不受影响场景。
- 环境、鉴权或外部依赖问题：完成当前权限内安全的启动、配置核对和日志排查后，交还责任边界、失败证据和所需条件。

每项修正或条件恢复后重跑原失败场景及受影响回归。复杂内部逻辑可以按风险补充白盒证据，但不能替代真实 HTTP 最终验收。

## 完成说明

按 API 或功能方向报告真实调用方式、已验证场景与数据来源、关键响应或副作用、失败定责、实际命令、未覆盖范围和阻塞条件。测试通过数与覆盖状态分开报告，不能用汇总 Green 隐去数据、环境或外部依赖缺口。
