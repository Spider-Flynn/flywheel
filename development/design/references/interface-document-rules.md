# Markdown 接口文档规则

仅在产出 Markdown 接口文档时使用本规则。

## 文档产出

1. 文件使用 `模块名接口文档.md` 或 `功能名接口文档.md` 命名，默认与技术设计一同存放在 `docs/powers/`。
2. 根据接口实际内容自然组织，不套固定模板，不强制标题数量、表格结构或章节顺序。
3. 每个接口完整表达接口基本信息、入参、出参、请求示例和响应示例；基本信息至少能说明接口用途、请求方法和请求路径，其他信息只在接口实际需要时补充。
4. 入参、出参和示例应让使用者能够理解并调用接口。字段只写已确认的类型、必填性、含义和必要约束；示例与字段定义保持一致。
5. 示例只具体化已确认的字段、约束和业务语义，不用看似真实的示例值补齐未确认规则，也不包含真实凭据、个人信息或其他敏感数据。
6. 无入参或无响应体时直接说明，不为了结构完整保留空标题、空表格或占位内容。

## 一致性与边界

1. Markdown 接口文档是接口契约的人类可读表达，不替代技术设计中的功能规则、核心数据、数据源规则和具体流程。
2. 现有接口二开时，以已确认的原接口结构为基础，只呈现本次确认后的有效契约，不记录新旧字段变更过程。
3. 文档完成只代表接口契约文件完成，不代表接口已经实现、部署、同步外部平台或通过 HTTP 验收。
